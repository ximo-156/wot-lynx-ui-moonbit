## 项目简介

moonlint 是一个用 MoonBit 写的配置驱动代码规范检查器，起源是 wot-lynx-ui 项目里一个查 Lynx 页面代码约定的 Node 脚本 review-lint.mjs。用 MoonBit 重写之后发现，光靠正则逐行匹配能查的问题很有限——这个 import 有没有被用到、两个文件是不是互相引用，都得把整个项目的代码过一遍才能下结论。于是又补了 JS/TS 的词法分析和结构化解析，把项目的 import 图建出来做跨文件检查。现在规则全部写在 JSON 配置里，内置 React、Vue、Angular、Svelte、Next.js、SolidJS、Astro、Nuxt 等 11 套预设，扫描模式覆盖目录树、git 改动、staged、glob 和 stdin，报告支持文本、JSON、GitHub 注解和 SARIF，重复扫描可以用 --incremental 只查内容变过的文件。

## 核心功能范围

- **行级规则**：contains、prefix、suffix、regex、equals、word 六种基础匹配器，加上 all、any、not 三种组合且可任意嵌套，一个 match 字段就能写出任意布尔表达式；unless 字段做负向豁免。每个规则的正则只编译一次，嵌套在组合里的正则也一样
- **文件级规则**：11 种检查——行数上限、行宽上限、行尾空白、tab、末尾换行、重复行、文件命名、文件大小、空文件、行尾格式、BOM。其中行尾空白、末尾换行、tab 支持 --fix 自动修复，修复保留原行尾格式并原子写入
- **跨文件结构规则**：自己实现的 JS/TS 词法分析器（字符串、模板串 ${} 插值、正则字面量都能正确切分）加结构化解析器，建出项目 import 图，支持 8 项检查——未使用的 import、重复 import、解析不了的相对路径、循环 import、../ 超过层数上限、require 调用、export default、没有任何文件引用的导出
- **配置体系**：JSON 配置；extends 支持递归继承，相对声明它的那个文件解析；include/exclude glob 作用域分全局和规则两级；预设之间、预设和自有规则之间按 id 合并去重，同一文件内 id 重复报错
- **扫描模式**：目录树（默认）、--changed（取 merge-base 以来的改动，读 HEAD blob 而不是工作区）、--staged（读索引真实内容）、--glob、--stdin/--stdin0。所有模式共用同一套路径规范化、去重、排序、扩展名和作用域过滤
- **注释处理**：匹配前把 // 和 /* */ 置空但保留行号列号；JS/TS 模式下识别模板串和插值，模板串里的 // 不当注释
- **内联禁用**：// moonlint-disable、disable-next-line、enable 三种语法，可带规则 id，行级和结构级 finding 都认
- **报告输出**：text、json、github、sarif 四种格式；--report 可额外落盘；--summary 按规则汇总；JSON 报告里每个被选中的文件都标明已扫描、跳过（带原因）或失败，不把失败偷偷算成干净
- **baseline 与增量缓存**：baseline 按 finding 哈希豁免存量问题；--incremental 按文件内容哈希加配置指纹缓存结果，配置一变全部失效，缓存损坏时降级为全量扫描并告警
- **测试**：270 个单元测试（wasm 目标下 265 通过，5 个因 wasm 没有 native FFI 失败）、160 个 CLI 集成测试分 9 组；CI 在 ubuntu 上跑 moon check、native 单测、native 构建和全量集成测试

## 移植或参考说明

- 行匹配与文件级检查的规则语义来自 wot-lynx-ui 的 review-lint.mjs，原脚本针对 Lynx 页面代码约定
- 与参考实现相比的自主设计：不跟随任何 Java 插件体系；lex.mbt、parse.mbt、analysis.mbt、cache.mbt 和匹配器组合 DSL 都是为这个项目新写的
- MoonBit 侧只依赖 moonbitlang/x；文件系统和 Git 访问走一个固定参数、不经过 shell 的 C 桥接层。MoonBit 生态里没有现成参照，词法分析器、import 图构建、增量缓存都是按 MoonBit 的类型系统和标准库能力重新设计的
