## 1. 背景与问题定义

MoonBit 2026 十月黑客松报名初审被驳回，驳回理由原文：

> "申报限定的核心仍以独立逐行匹配和简单文件属性检查为主，不足以支撑所要求的独立项目工程深度。"

组委会允许在 **2026-10-31 前补充材料重新审核**。

**问题定义**：这不是"补几个功能"的问题，而是需要在评审可验证的证据链上，证明 moonlint 是一个**有独立工程深度的静态分析项目**，而非行匹配工具的包装。工程改造代码已于 2026-10-24 完成并入库（v0.2.0，commit `97c07fc`），当前项目处于"**代码就绪、验证进行中、材料未提交**"的状态。

## 3. 目标与验收标准

**总目标（SMART）**：在 2026-10-31 截止前，提交补充材料并通过初审。

**完成的定义（Definition of Done）**——四项全部满足才可提交：

| # | 验收标准 | 验证方式 |
|---|---|---|
| DoD-1 | CI 全绿；若有失败，每个失败都有书面解释且不影响主张 | GitHub Actions 页面截图/链接 |
| DoD-2 | 补充材料按组委会要求的渠道与格式提交，并取得回执 | 邮件/系统回执 |
| DoD-3 | 驳回理由中每个关键词都有材料内可点击的证据链接 | 见 §7 映射表逐条核对 |
| DoD-4 | "模拟评审人"按 5 分钟走查路径无卡点地理解项目深度 | 见 §7.3 走查记录 |

## 7. 沟通与呈现策略

### 7.1 核心叙事（一句话）

> moonlint 是一个四层静态分析引擎：**词法/语法层**（lex/parse）→ **项目分析层**（import 图、8 项跨文件检查）→ **规则引擎层**（行/文件/结构三类规则 + 布尔 DSL）→ **增量缓存层**（内容哈希 + 配置指纹），行匹配只是其中最基础的一层。

### 7.2 驳回理由关键词映射表（材料必含）

| 驳回理由关键词 | 回应 | 证据（材料中可点击） |
|---|---|---|
| "独立逐行匹配" | 行匹配仅为四层之一；上有完整 tokenizer/parser 与 import 图 | `lex.mbt`、`parse.mbt`、`analysis.mbt`、README Architecture |
| "简单文件属性检查" | 文件级 11 项检查之上，新增 8 项**跨文件**结构检查 | `types.mbt` StructuralCheck、`presets/imports.json` |
| "工程深度不足" | 分层架构 + 增量缓存（内容哈希+配置指纹）+ 匹配器组合 DSL + 277 单测 + 164 集成测试 + CI 门禁 | `CHANGELOG.md` 0.2.0、`.github/workflows/ci.yml` |

### 7.3 模拟评审人 5 分钟走查路径

1. 打开 README → 30 秒内看到"逐行匹配之外的四层"主张（Origin 段第 2 句 +
   Features 区 Cross-file structural rules 一条）
2. 点 Architecture 章节 → 看到模块分层图与各层职责
3. 点 CHANGELOG → 0.2.0 的 Added 清单即证据索引
4. 点 `analysis.mbt` → 8 个 check 函数是真实程序分析，不是字符串匹配
5. 点 Actions 标签页 → CI 绿 = 测试与工程规范的自证
   （当前状态：账户账单锁定导致作业无法启动，见 R1；解除锁定后此项才成立）

## 9. 团队与协作机制

单人项目也要有角色定义，防止"既是运动员又是裁判"：

| 角色 | 担任者 | 职责 |
|---|---|---|
| 项目负责人 | 用户 | 决策、对外提交、最终验收 |
| 执行负责人 | AI 助理 | 开发、测试、文档、材料撰写 |
| 模拟评审人 | AI 助理（按驳回理由扮演） | 独立视角挑刺，专查"评审人能不能看懂深度" |

**每日异步站会**（三问，记录于本文件或对话中）：
1. 昨天完成了什么（对照里程碑）？
2. 今天计划做什么（对照排期）？
3. 有什么阻塞（对照风险册）？

**升级机制**：出现以下情况必须升级到项目负责人决策，不自行消化：
- CI 修复超过 1 个工作日仍不绿；
- 材料被组委会二次驳回或要求大改；
- 任何需要"对外承诺"的动作（提交即视为承诺）。
