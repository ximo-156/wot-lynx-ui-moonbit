## 范围

本记录描述初始 MVP 验证时的工作区状态，并非已发布版本、当前工作区或远程 CI 结果。原有 moonlint 入口保持完整；MoonImpact 是新的 CLI 和计划模式，并非给 lint 规则集改名。本次验证没有进行项目提交、推送、注册提交或依赖安装。

环境：macOS Native、moon 0.1.20261104、moonc v0.10.20+65efd5b93、Node v22.23.2。可选的真实运行检查使用已有且可信的 Vitest 3.2.7 包，所有演示源码、运行器配置、缓存和故障注入均隔离在自有临时目录中。没有运行业务测试。

## 功能证据

[合成演示](<../examples/impact-demo/README.zh-CN.md>)包含三个测试文件和四个测试：

| 变更 | 计划策略 | 选中的测试文件 | 证据 |
| --- | --- | --- | --- |
| 费用计算模块 | related | 费用测试 + 汇总测试（2/3 个文件） | 直接导入和一条包含两条边的传递链 |
| 主题 CSS | related | 主题测试（1/3 个文件） | 配置的根目录读取器文件输入，并非模块导入 |
| 包清单或缺失/已删除的输入 | full | 清单中的完整集合 | 明确的全局输入 / 缺失输入回退原因 |

在隔离演示中实际执行 Vitest 验证了以下内容：

- 费用变更：两个测试文件 / 三个测试通过，CLI 退出码为 0。
- CSS 变更：一个测试文件 / 一个测试通过，CLI 退出码为 0。
- 向合成费用函数注入 `return 0`：相同的选中测试文件检测到了两个受影响的失败断言，CLI 退出码为 1。负时长断言仍然通过。
- 对该故障夹具运行完整回归，同样检测到了两个失败断言（样式表测试仍然通过）。
- 对该合成 CSS 输入，Vitest 3.2.7 的 `related --run src/theme.css` 报告没有测试文件；MoonImpact 通过文件输入边选中了主题测试。此观察仅针对该夹具和已安装版本。
- JSON 标准输出仍是可解析的建议性计划，Vitest 输出则发送到标准错误。仅生成计划时的退出码 0 没有被表述为测试成功。

可重复运行的可选冒烟检查是 [impact_vitest_smoke.py](<../tests/impact_vitest_smoke.py>)。它要求明确提供已安装的依赖，不会安装任何内容。它也会打印针对 CSS 输入与 `vitest related` 的比较；这是特定依赖覆盖能力的演示，并非通用基准测试，也不是声称 MoonImpact 可以替代 Vitest。

## 真实项目只读评估

提供的 unibest 配置是 [impact-unibest.json](<../examples/impact-unibest.json>)。所记录的运行使用了两个明确变更：退款页面和全局主题 SCSS。观察结果如下：

| 指标 | 记录值 |
| --- | ---: |
| 已分析的源文件 | 618 |
| 已知依赖边 | 2,241 |
| 测试文件清单 | 291 |
| 已知受影响图节点（含输入） | 25 |
| 不确定性观察项 | 319 |
| 实际策略 | full |

计划包含指向退款、页头/主题及其他相关测试的已知读取来源链接，但**不声称这些链接完整**。动态读取、目录扫描、不支持的样式依赖，以及所选范围之外的输入，都会触发完整回退。因此，这个首个 MVP **尚未**证明能在 unibest 上安全地减少全项目测试数量。一次本地运行中生成计划约耗时 0.9 秒；这不是执行速度基准测试。

只有合成夹具执行了测试。unibest 在只读计划评估前后的 Git 状态完全相同。不要将其私有业务源码或私有报告细节作为公开演示的一部分发布。

## 自动化覆盖

- 原生单元测试套件：在最终 `moon info && moon fmt`、类型检查和重新构建后，462 个通过。仍有编译器警告；这里并不声称没有警告。
- [MoonImpact CLI 回归](<../tests/impact_integration.py>)：15 个通过。
- [原生桥接回归](<../tests/impact_native.py>)：15 个通过，涵盖 Git 路径/引用处理、进程参数、超时清理、默认不执行行为，以及并发竞争下仅创建报告的发布。
- 原有 moonlint CLI 回归套件：207 个通过。

原生桥接会拒绝仓库的 clean/process 过滤器，以免 Git diff 调用它们。默认计划不会执行 Node 代码。显式 `--run` 不是沙箱，只应在可信项目中使用。

剩余边界包括动态 I/O、广泛的 CSS/框架生成依赖、JSX/TSX 解析、针对删除的历史图重建、Windows 支持，以及自动发现测试运行器配置。新增支持必须保持保守回退，不能把缺失分析变成自信的无影响结论。
