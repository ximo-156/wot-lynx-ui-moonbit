## 逐条审查

### 01 MoonBit 为主 —— 通过

以 MoonBit 作为项目主要实现语言。

证据：

- 实现代码 8,115 行，全部为 `.mbt`（36 个文件，不含 3,011 行白盒测试）。
- `moon.mod` 声明唯一依赖为 `moonbitlang/x`（json/time 等官方库），无外部运行时依赖。
- 仓库内唯一的非 MoonBit 源文件是 `git_native.c`（905 行）：`lstat`、Git
  blob 读取与原子写的 C FFI 桥，因为 MoonBit 标准库尚不暴露这些系统调用。
  MoonBit 与 C 的比例约 9:1，"为主"无争议。
- `tests/integration.py` 是 CLI 的黑盒测试 harness，不属于项目实现。

### 03 能够运行 —— 通过（本次审查后加固）

提供清晰 README、可运行示例与必要测试。

证据：

- README 覆盖安装、用法、全部规则类型、预设表、扫描模式、配置继承、
  auto-fix、CI 输出与仓库结构。
- **`examples/demo`（本次新增）**：一个 3 文件 TypeScript 演示工程，
  在随附配置下产生 7 条可手推的 finding，覆盖行规则（含 `match_comments`
  与 `unless` 抑制）、文件规则、结构规则三类规则；`examples/README.md`
  给出运行命令与逐字节预期输出，并附第四层（增量缓存）的完整走查——
  哪些发现入缓存、哪些每次现算、内容哈希如何键控。
- **测试**：277 个白盒单元测试（wasm-gc 目标 272 通过 / 5 个为 wasm 缺
  native FFI 的已知失败）+ 164 个 CLI 集成测试方法（10 个阶段，其中
  `demo` 阶段把演示工程的完整报告文本与增量缓存往返钉死）。
- **CI**：`.github/workflows/ci.yml` 在 ubuntu 上安装 MoonBit 工具链，
  依次执行 `moon check` / `moon test` / `moon info` / `moon build --target native`
  / 全量集成测试——集成测试终于有了在 native 目标上运行的机会（本机
  无 MSVC，此前只能跑 wasm）。
- **CI 现状（2026-10-24 22:00 经 GitHub API 核实）**：10-24 的 5 次运行
  （含 0.2.0 核心提交 `97c07fc`）**全部失败，且失败原因与代码无关**——
  Actions 注解原文："The job was not started because your account is locked
  due to a billing issue." 作业从未启动（每次约 2 秒即失败，无任何步骤
  执行）。**用户需先在 GitHub 账户设置中解除账单锁定**，CI 才能运行；
  在锁定解除前，CI 无法作为"测试通过"的证据，验收标准 03 的 CI 一项
  暂时只能以"工作流已就绪、待账户解锁"的状态呈现。

可复现的演示。

## 本次审查发现并已修复的问题

1. **`--init` 首跑路径失效（P0，已修复）**：行规则匹配的是注释置空后的源码视图，
   而 `--init` 生成的 `common/no-todo-comment` 规则永远打不中 `// TODO` 注释——
   新用户第一次运行就会看到"规则毫无反应"。修复：新增 `match_comments`
   规则选项（`1f56d28`），默认关闭以保持既有语义，纳入缓存指纹，配 6 个单元测试。
2. **无可复现演示（P0，已修复）**：新增 `examples/demo` 与钉死预期输出的
   集成测试（`6a0b957`）。
3. **出处声明不完整（P1，已修复）**：README 现含来源仓库链接、MIT 许可证、
   同一作者关系与原创性声明（`48ca389`）。
